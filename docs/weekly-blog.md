# 주간 블로그 발행 운영

매주 월요일 오전 10시(Asia/Seoul), 이 Codex 작업의 예약 실행에서 글 1편을 작성하고 검증한 뒤 GitHub `main`에 푸시한다. 컴퓨터와 Codex 앱이 실행 중이어야 한다. 웹사이트 공개는 호스팅의 GitHub 자동 배포 연결이 필요하며, 푸시 성공과 실제 페이지 공개를 구분해 확인한다.

## 콘텐츠 저장

- 글: `src/content/blog/posts.json` 배열에 새 객체 추가. 기존 글과 URL을 보존한다.
- 이미지: `public/blog/<slug>/`에 서로 다른 실제 이미지 파일 2개 이상 저장한다.
- 블로그 목록, 상세 페이지, 사이트맵은 저장소 글 전체를 읽는다. WordPress 설정은 블로그를 변경하지 않는다.
- `id`, 영문 소문자 하이픈 `slug`, `title`, `excerpt`, `content`(HTML), `date`(한국 날짜), `author`, `category`, `primaryKeyword`, `secondaryKeywords`, `publicationWeek`, `featuredImage`, `images`를 작성한다.
- `publicationWeek`는 발행일이 포함된 주의 월요일 날짜다. 실행 재시도 시 같은 주의 글이 원격에 있으면 추가하지 않는다. 미완성 로컬 글이 있으면 이어서 완성한다.
- `images`는 `{ "src": "/blog/<slug>/image.webp", "alt": "구체적인 한국어 이미지 설명" }` 배열이다. 두 이미지 모두 본문에 `<figure><img src="..." alt="..." width="..." height="..." loading="lazy"><figcaption>...</figcaption></figure>`로 포함한다.

## 작성 기준

1. 기존 제목과 `primaryKeyword`를 확인해 중복 검색 의도를 피한다. “강남 달토”, “강남 가라오케”를 바탕으로 주제에 맞는 대표 롱테일 1개와 보조 키워드 2~4개를 선정한다. 검색량을 조사하지 않았다면 검색량이나 순위를 주장하지 않는다.
2. 본문은 HTML 태그를 제외하고 공백을 정규화한 기준 2,700~3,300자, 목표 약 3,000자로 작성한다. 제목에 대표 롱테일을 자연스럽게 포함하고 본문에는 두 기본 키워드를 문맥에 맞게 사용한다. 반복 문장이나 키워드 나열로 분량을 채우지 않는다.
3. 요금, 예약, 위치, 첫 방문, 인원별 준비 사항을 번갈아 다루되 해당 검색 의도에 구체적으로 답한다. 소제목 3개 이상과 관련 내부 링크 2개 이상을 넣는다.
4. 실제 영업 정보는 현재 한국어 사전과 페이지에서 확인한다. 기본 주대와 총비용을 구분한다. 확인하지 않은 가격, 무료 서비스, 거리, 후기, 방문 경험, 인원 수용 능력, 할인 기간을 만들지 않는다. 시점이 중요한 정보는 근거를 확인하고 불확실하면 문의가 필요한 사항으로 표현한다.
5. imagegen 스킬로 글에 맞는 서로 다른 이미지 2개 이상을 생성하거나 사용 권한이 확인된 관련 원본을 사용한다. 생성 이미지는 “이해를 돕기 위한 이미지”라고 캡션에 표시하며 실제 매장 사진으로 소개하지 않는다. 실존 인물·고객 후기나 정확하지 않은 지도를 만들지 않는다. 생성 결과는 검사 후 저장소에 복사한다. 단순 복제 파일을 두 이미지로 계산하지 않는다.
6. 대표 이미지와 본문 이미지, 설명, 날짜가 일치해야 한다. 이미지 생성 실패 시 조건을 낮춰 발행하지 말고 실패 원인을 알린다.

## 후보 주제

아래는 검색 의도에 따른 후보이며 검색량이 검증된 목록은 아니다. 기존 글과 겹치면 다른 관점을 선택한다.

- 강남 달토 첫 방문 예약 준비사항
- 강남 가라오케 주대와 총비용 차이
- 강남 달토 오후 9시 이전 방문 체크사항
- 강남 가라오케 소규모 모임 예약 질문
- 강남 달토 위치와 주차 문의 방법
- 강남 가라오케 이용 시간과 예산 계획
- 강남 달토 인원 변경 시 예약 확인사항
- 강남 가라오케 단체 모임 준비 체크리스트

## 검증 및 발행

`npm run validate:blog`, `npm run test:blog`, `npm run build`를 실행한다. 생성 HTML에서 새 글의 본문 이미지, title, description, Article 이미지, canonical, 사이트맵 URL을 확인한다. 새 글과 이미지 파일을 검토한 뒤 해당 변경만 커밋하고 강제 푸시 없이 `origin main`에 올린다. 사용자 작업을 덮어쓰거나 임의로 포함하지 않는다.

원격 변경이 있으면 먼저 안전하게 통합한다. 기본 브랜치에 같은 주 글이 이미 있으면 추가 발행하지 않는다. 정상 푸시 후 사이트의 실제 새 글 URL을 확인하고, 미반영이면 “저장소 업로드 완료, 배포 확인 필요”로 보고한다. 발행 성공 시 URL·주제·실제 글자 수·이미지 수·커밋을 알리고, 실패나 필요한 사용자 조치가 있을 때 알린다. 변화 없는 재실행에는 알림을 반복하지 않는다.
